# 多租户实例编排

> 形态：**一份代码 + 每租户一个独立数据目录/数据库/进程 + 子域名访问**。
> 对应 `tenants` 表的 `instance_state`：`pending → provisioned → running → stopped`。

## 1. 目录结构

```
<repo>/                      # 共享代码（唯一一份，git pull 即全量升级）
  server.js
  src/
  public/
  tenants/                   # 已 gitignore，不进版本库
    t-202611-847f/           # 租户目录（code 小写）
      .env                   # 端口、独立库路径
      app.pid                # 运行中的进程 pid
      data/
        crm.db               # 该租户的独立数据库
```

> 为什么不给每个租户复制一份代码：升级要覆盖 N 次，必然漏。共享代码 + 独立数据目录，升级只需滚动重启。

## 2. 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `TENANT_ROOT` | `<repo>/tenants` | 租户目录根 |
| `TENANT_PORT_BASE` | `18200` | 端口分配起点（取当前最大端口 + 1） |
| `TENANT_PUBLIC_BASE` | `crm.example.com` | 子域名后缀，租户访问地址为 `<code小写>.<该值>` |
| `CRM_SECRET` | — | 加密租户初始管理员密码用，**务必设置且不要更换** |

## 3. 命令

```bash
# 建实例（只建目录/库/管理员，不启动）
npm run provision:tenant -- --code=T-202611-847F
npm run provision:tenant -- --all-pending        # 批量处理 pending/failed

# 启停与健康检查
npm run tenant:ctl -- start  --code=T-202611-847F
npm run tenant:ctl -- stop   --code=T-202611-847F
npm run tenant:ctl -- status --code=T-202611-847F

# 验收（真实建实例 → 启动 → 登录 → 停止）
npm run test:provision
```

编排成功后返回：

```json
{
  "ok": true,
  "code": "T-202611-847F",
  "port": 18201,
  "dir": "/srv/mserm-crm/tenants/t-202611-847f",
  "subdomain": "t-202611-847f.crm.example.com",
  "adminUser": "admin",
  "adminPassword": "XXXXXXXXXXXX",
  "url": "http://127.0.0.1:18201"
}
```

> 管理员密码只在这里出现一次；同时以 AES-256-GCM 密文存入 `tenants.admin_password`，重复编排可还原（`CRM_SECRET` 变更后旧密文解不开）。

## 4. Nginx：通配符子域名

租户少时每个租户单独一个 `server` 块；租户多了用 `map` 生成。

```nginx
# /etc/nginx/conf.d/tenants.map  —— 由编排器生成/追加
map $host $tenant_port {
    default 0;
    t-202611-847f.crm.example.com 18201;
    t-202611-8a2c.crm.example.com 18202;
}

server {
    listen 80;
    server_name ~^(?<sub>[a-z0-9-]+)\.crm\.example\.com$;

    location / {
        if ($tenant_port = 0) { return 404; }
        proxy_pass http://127.0.0.1:$tenant_port;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 60s;
    }
}
```

```nginx
http {
    include /etc/nginx/conf.d/tenants.map;
}
```

HTTPS：用通配符证书 `*.crm.example.com`，把上面的 80 改成 443 并加 `ssl_certificate`。

## 5. systemd 模板（生产推荐）

`/etc/systemd/system/mserm-tenant@.service`：

```ini
[Unit]
Description=MSERM CRM tenant %i
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/mserm-crm
EnvironmentFile=/srv/mserm-crm/tenants/%i/.env
ExecStart=/usr/bin/node --no-warnings server.js
Restart=always
RestartSec=3
MemoryMax=350M
TasksMax=128
NoNewPrivileges=true

[Install]
WantedBy=multi-user.target
```

```bash
systemctl enable --now mserm-tenant@t-202611-847f
systemctl status mserm-tenant@t-202611-847f
```

> 用 systemd 时不要再跑 `tenant-ctl start`，否则会有两个进程抢同一端口。二选一。

## 6. 健康检查

```
GET /healthz
→ { "ok": true, "service": "mserm-crm", "db": "sqlite", "uptime": 12, "now": "..." }
```

用途：Nginx upstream 检查、编排器启动确认、监控告警。**不鉴权、不查业务表**，开销可忽略。

## 7. 资源与容量

- 每实例常驻约 **80–150 MB**；`MemoryMax` 建议 350M（留峰值余量）。
- 每租户数据库 50–200 MB（随业务增长）。
- 端口从 18200 起递增；回收租户后端口不自动复用（可手工改 `tenants.port`）。
- 50 个付费租户 ≈ 5–8 GB 内存 + 10 GB 磁盘，规划时留 2 倍余量。

## 8. 升级、备份与回收

**升级**（共享代码）：

```bash
cd /opt/mserm-crm && git pull
# 逐个滚动重启；启动时 migrate() 自动加列/建表，不删数据
for t in $(ls tenants); do systemctl restart mserm-tenant@$t; sleep 2; done
```

**备份**（每租户独立）：

```bash
# 方式一：逻辑快照（推荐，跨库/跨引擎可读）
CRM_DB=tenants/t-202611-847f/data/crm.db npm run backup
# 方式二：停服后复制 crm.db（连同 -wal/-shm 或先停服）
```

> `src/backup.js` 现已做「库内实际表 vs 备份清单」自检，漏表会直接中止。

**回收**：

```bash
npm run tenant:ctl -- stop --code=T-202611-847F
# 保留 30 天后归档/删除 tenants/t-202611-847f
tar czf /backup/t-202611-847f-$(date +%F).tgz tenants/t-202611-847f
rm -rf tenants/t-202611-847f
```

## 9. 与官网的衔接

1. 会员付费 → 官网确认到账 → 调 CRM `POST /api/internal/tenant/activate`。
2. CRM 写入 `tenants` 台账，`instance_state=pending`。
3. 编排器执行 `provision:tenant --all-pending`，建实例 → `provisioned`。
4. 启动后 → `running`；官网可展示子域名与初始账号。
5. 到期 → 官网调 `suspend` → 停止进程（保留数据）→ 30 天后归档。

> 第 3 步目前是**手动/定时执行**；若要做成"支付后自动部署"，把它挂到 `activate` 之后或独立队列（P2）。

## 10. 已知限制

- 单机部署：所有租户共享一台机器的 CPU/内存/磁盘，无跨机调度。
- 端口分配取 `max(port)+1`，高并发编排需加锁（当前串行执行即可）。
- 未做租户级流量限速（可在 Nginx 加 `limit_req`）。
- 未做自动备份调度（可用 cron 调 `npm run backup`）。
