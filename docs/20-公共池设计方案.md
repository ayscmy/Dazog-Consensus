> **状态**：三项决策已确认（见 4.1），**仍为设计方案，未改任何代码**。
> **范围**：用户确认「两个都做」——A 是 CRM 内企业线索再分配，B 是官网侧真实商业线索池。

## 0. 一句话与边界

**两个池解决两件事，不能合并成一张表**：

| | A · CRM 线索公海 | B · 官网真实商业线索池 |
|---|---|---|
| 归属 | 一套 CRM 部署**内部** | 官网**平台侧** |
| 池里是什么 | 本企业未认领 / 超时未跟进的线索 | 官网发布的**真实商业线索**（有来源、有授权、有限领） |
| 谁领 | 该企业组织内的成员 | 官网注册会员（**必须已开通**） |
| 领了之后 | `owner_id` 从 NULL 变成自己，仍在原库 | 写入会员自己的 CRM（在线试用 / 本地部署），成为一条私有线索 |
| 目的 | 线索不屯积、不流失 | 用真实商机养用户，把免费会员推成付费/授权用户 |

两端通过**内部接口 + 对外线索 API** 单向打通（B → A），官网不直连 CRM 数据库，沿用现有 `X-Internal-Key` + 回环 IP、以及 `X-Api-Key` + IP/域名白名单两套安全模型。

## 2. 设计原则（六条）

1. **不新增 `pool` 主表**：A 用 `leads.owner_id IS NULL` 表示「在池中」，一张表一个真相。
2. **池状态与业务状态正交**：不往 `status` 里塞 `in_pool`，否则污染现有状态机。
3. **规则走 `settings` 不走 `.env`**：`src/settings.js` 已有 `DEFAULTS` + `SETTING_LABELS` + 后台设置页，改规则不用重启。
4. **组织隔离沿用 `org_units.path` 前缀**：`scopeFilter` 对 `self` 角色必须换一套 `poolWhere()`。
5. **公海是再分配机制，不是惩罚机制**（`docs/05:304`）：所有回收留痕、可查；**无效线索不回池**。
6. **真实线索必须可追责**（v2 新增）：每条线索有来源、授权凭证、有效期；领取有人、有时、有 IP、有用途承诺。**没有授权凭证的线索不允许上架**——这是把「素材池」换成「真实商业线索池」后新增的硬约束。

## 3. A · CRM 线索公海

### 3.1 数据模型

`leads` 增 4 列（新库写进 `SCHEMA_DDL`，老库走 `COLUMN_PATCHES` 自动补）：

| 列 | 类型 | 含义 |
|---|---|---|
| `pool_at` | TEXT | 最近一次入池时间（NULL = 从未入池） |
| `pool_reason` | TEXT | `new` / `first_touch_timeout` / `timeout` / `release` / `reclaim` / `api` |
| `pool_count` | INTEGER DEFAULT 0 | 累计入池次数 |
| `claim_at` | TEXT（已有） | **复用**为最近一次领取时间 |

新建 `pool_events` 审计表（**不复用 `activities`**：跟进记录混杂在一起，没法统计「每周领取数」）：

```
pool_events(id, lead_id, org_id, actor_id, action, reason, from_owner, to_owner, created_at)
-- action: claim | release | assign | reclaim | auto_reclaim | api_in
-- 索引: (actor_id, created_at)；(lead_id, created_at)
```

`leads.org_id NOT NULL` 不变：入池只清 `owner_id`，组织归属不动。

### 3.2 状态机（双时钟，正交于 `status`）

```
                    ┌────────────────── 池中 owner_id = NULL ──────────────────┐
                    └───┬───────────────┬──────────────────┬──────────────────┘
       新建/API 推入 ───┘               │                  │
       （未指定负责人）          领取 claim / 分配 assign     │
                                       ▼                  │
                    ┌────── 私有 owner_id = X, claim_at = now ──────┐        │
                    │  status: new → contacted → qualified → converted│        │
                    └──┬──────────┬──────────┬──────────┬───────────┘        │
           手动放回 release ─┘      │      │      │                          │
           72h 无首触 ─────────────┘      │      │      判无效 invalid ──► 终止（不回池）
           30 天无有效跟进 ───────────────┘      │
           经理强制回收 reclaim ─────────────────┘
                                                  └──────────────► 回到池中
```

| 时钟 | 起点 | 阈值 | 动作 |
|---|---|---|---|
| 首触时钟 | `claim_at` | 24h 无跟进 | 只提醒本人与经理，**不回收** |
| 首触时钟 | `claim_at` | 72h 仍无 `last_activity_at` | 回池，`pool_reason='first_touch_timeout'` |
| 跟进时钟 | `coalesce(last_activity_at, claim_at)` | 30 天无有效跟进 | 回池，`pool_reason='timeout'` |
| 保护期 | `claim_at` | 7 天内 | 屏蔽上面两条回收 |

**「有效跟进」定义**：`activities` 中 `target_type='lead'` 且 `type ∈ (call, visit, email, meeting, wechat)`；`note` 不算。现有 `POST /api/leads/:id/activity` 已更新 `last_activity_at`，只需按类型判定是否续时钟。

**修正 `docs/05`**：原图把「判无效」也画成回公海（`docs/05:108`），本方案改为**无效即终止**。

> **坑（历史上踩过）**：`/api/leads/:id` 会吃掉 `/api/leads/pool`。`src/routes/index.js` 里 `import './pool.js'` **必须排在 `import './leads.js'` 之前**。之前 `/api/internal/trial/ping` 被 `:id` 吃掉是同一个问题。

**领取必须原子**：用 `update leads set owner_id=?, claim_at=?, ... where id=? and owner_id is null` 的受影响行数判断是否抢到（SQLite `changes` / PG `rowCount`），并发两请求只有一个成功。领前一次性校验模块权限、组织可见性、在库上限、每周上限、账号状态（`frozen` 不可领）。

### 3.5 权限矩阵（对齐 `src/auth.js` 的 `ROLES`）

| 动作 | admin / gm (`all`) | director / manager (`org`) | ae / sdr (`self`) | trial (`org`) | finance / legal |
|---|---|---|---|---|---|
| 查看公共池 | 全集团 | 本组织子树 | **本组织池**（非他人私有） | 自己试用组织 | ✗ |
| 领取 | ✓ | ✓ | ✓ | ✓ | ✗ |
| 放回自己的 | ✓ | ✓ | ✓ | ✓ | ✗ |
| 分配给他人 | ✓ | ✓ | ✗ | ✗ | ✗ |
| 强制回收他人 | ✓ | ✓ | ✗ | ✗ | ✗ |
| 改规则参数 | ✓ | ✗ | ✗ | ✗ | ✗ |

`scopeFilter()` 对 `self` 返回 `owner_id = 自己`，池中线索恒为假。必须新增 `poolWhere(user)`：`all` → `1=1`；`org` / `self` → 一律 `org_id IN (SELECT id FROM org_units WHERE path LIKE ?)`。`self` 角色**看得到本组织池、看不到他人私有线索**。`trial` 角色 `scope='org'`，天然只看自己那份独立试用组织。

### 3.6 定时回收（`src/pool.js`）

- `startPoolJanitor()` 在 `server.js` 与 `startTrialJanitor()` 并列注册，**每小时一次**。
- 扫描 `owner_id IS NOT NULL` 且 `status NOT IN ('converted','invalid')`，按 3.2 双时钟判断，保护期内跳过。
- 回池：清 `owner_id`、写 `pool_at` / `pool_reason` / `pool_count+1`、写 `pool_events`、写 `activities(type='note')` 留痕。
- 提前 `pool.notify_before_days` 天写提醒。通知表当前不存在，站内信/邮件/短信提醒列 P2。
- 启动横幅打印规则摘要。

### 3.7 外部线索 API 衔接（A 的主要入口）

`src/routes/leads-api.js:73-88` 的 `resolveOwner()`：

- 带 `owner_id` → 校验后挂给该人（现状不变）
- 未带、接入方有 `owner_id` → 用默认负责人（现状不变）
- **未带且无默认负责人** → 不再报错，**入公共池**（`owner_id=NULL`, `pool_reason='api'`, `pool_events(action='api_in')`）
- `api_clients` 加 `pool_on_missing`（默认 `1`），显式 `0` 保留旧报错行为；后台「API 接入」表单加勾选项

### 3.8 试用联动与「养用户 → 收费」钩子

1. **示例数据入池**：`seedSampleData()` 的 5 条示例线索改为 **3 条归自己、2 条入池**（`owner_id=NULL`, `pool_at=now`, `source='示例'` 不变）。
2. **D1 邮件话术**加一句「公共池里有 2 条待领取的示例线索」。**邮件总数仍 5 封，不新增**。
3. **团队台阶**：点「分配给同事」时若组织内仅 1 人 → 提示「添加同事一起用，社区版 10 人以内免费」；第 11 人由 `src/edition.js` 的 `userQuota()` 提示并跳 `UPGRADE_URL`。公共池是把「一个人用」推成「一个团队用」的第一级台阶，成员数正是收费分界线。
4. **冻结态**：`frozen` 账号禁止领取与写入（登录已被 `src/auth.js:271` 拦住）；付费恢复后原数据原样回来。

## 4. B · 官网真实商业线索池（v2，决策已确认）

### 4.1 三条决策与落地方式

| 用户决策 | 落地 |
|---|---|
| **真实商业线索池**（不做素材池） | 池里是**有来源、有授权、可跟进成交**的真实商机线索；一期就做，不再分「素材池一期 / 真实池二期」。由此引入 4.2 的六条硬规则 |
| **必须已开通试用才能领** | 领取接口硬性校验；下载版用户按 4.5 的「等价判定」处理 |
| **下载版（本地部署）通过 API 接口开通** | 新增 4.5 的 API 接入通道，复用 `docs/15` 的 API Key + 授权 IP + 授权域名白名单体系，仅超管可审核开通 |

**明确不动官网现有 `leads` 表**：它是注册时写入、供我方后台销售跟进的线索（`src/db.js:319`），语义相反，混用会污染后台销售列表。B 另建表。

**资讯采集模块已删除、不恢复**（用户 11-07 决定）：池条目由后台人工录入 / 批量导入并**逐条登记来源与授权凭证**，不做自动采集。

### 4.2 真实线索特有的六条硬规则（v2 新增，因「真实」二字必须有）

1. **独家 / 共享分层**，解决「同一条线索被谁领」：
   - `exclusive=1` 独家：全站仅 1 人可领，先到先得，领取后 `status='taken'`，其他人看到「已被领取」
   - `exclusive=0` 共享：`max_claims`（默认 3）人可领，每人拿到一份独立副本
   - `claim_count` 原子递增，**达到上限立即停止领取**
2. **脱敏分级**：公开列表只显示行业 / 地区 / 需求摘要 / 预算区间 / 企业规模 / 发布时间；**公司全称、联系人、电话只在领取成功后的「已领取」视图里披露**。`contact`/`contact_phone` 原文绝不出现在公开接口响应中。
3. **来源授权必填**：每条线索登记 `source`（自有 / 合作 / 公开征集）、`consent_ref`（授权凭证编号）、`consent_expires_at`。**后台发布时未填授权凭证不允许上架**（前端 + 服务端双校验）；授权到期自动下架，已领取记录保留但不再新增领取。
4. **领取协议与用途承诺**：领取前必须勾选《线索使用协议》——「仅用于自身业务跟进，不得转售、不得用于对外提供服务」。落库 `agreed_at` + 协议版本号 + 领取 IP。页面底部固定免责声明。
5. **质量回收**：会员可标记「无效 / 联系不上 / 已成交」；同一条被标记无效累计 `POOL_INVALID_THRESHOLD`（默认 3）次自动下架并通知运营复核；「已成交」用于评估池质量，不做强制。
6. **反作弊**：领取接口叠加官网已有 `throttle`/`hit` 限流（`src/http.js`），按会员 + IP 双维度；设「持有未跟进数」上限（默认 10），领了不跟就不能再领；同一邮箱批量注册由注册链路现有校验拦截。

> 4.2 是按「真实商业线索」的合规要求补的保守设计。**若你希望简化（例如不做独家分层、不要协议勾选），告诉我删哪几条**——但来源授权必填与脱敏分级建议保留，这两条是真实线索与素材池的分界线。

| POST | `/api/my/pool-api` | 登录 | 会员申请 API 接入（填 IP / 域名 / 模式），落 `status='pending'` |

### 4.5 三条承接通道（v2 核心）

**「必须已开通试用才能领」的等价判定**（这里有个必须说清的歧义）：下载版用户在本地部署 CRM，**没有官网的在线试用组织**，强求 `trial_accounts.status='active'` 没有意义。因此按通道分别判定，门槛等价（都是「先在官网完成一次开通动作、留下可追责的身份」）：

| 通道 | 领取资格（等价门槛） | 用途 |
|---|---|---|
| 1 · 在线试用 | `trial_accounts.status='active'`（用户确认的硬条件） | 官网注册即开的那套 CRM |
| 2 · 下载版 API 拉取 | `pool_api_clients.status='active'` 且已审核通过 | 本地部署、通常无公网入站 |
| 3 · 下载版 API 推送 | 同 2，另需登记 CRM 公网 `base_url` + 密钥 | 本地部署有公网可达地址 |

三者共同前置：**官网注册会员 + 邮箱已验证 + 已同意《线索使用协议》 + 未被限流**。若你希望下载版也必须真的开一个在线试用账号才准领，告诉我，我把通道 2/3 的门槛改成「同时要求 active 试用账号」。

**通道 1 · 在线试用（内部接口）**

CRM 侧 `src/routes/trial-api.js` 新增：

```
POST /api/internal/trial/:id/pool-lead
```

- `X-Internal-Key` + `timingSafeEqual` + 回环 IP，路由 `{ auth: false }`
- 校验 `trial_accounts.status='active'`；`frozen` / `revoked` 拒绝并返回明确 code，官网据此提示「账号已冻结，恢复后继续」
- 往该试用组织 `insert into leads(...)`，`owner_id = 试用用户`，`source='官网公共池'`，`external_id='pool:<claim_id>'`（`leads` 已有 `uq_lead_external` 唯一索引，天然幂等）
- **不填** `pool_at` / `pool_reason` —— 它是私有线索，**不进 CRM 公海**

**通道 2 · 下载版 API 拉取（默认，推荐）**

本地 CRM 主动调用官网 `GET /api/v1/pool/claims?since=...`，带 `X-Api-Key`；官网按 `client_id` 反查 `member_id`，**只返回该会员自己领取过的、尚未同步的线索**，不能遍历全池（防凭证泄露拖库）。本地 CRM 收到后写入自己的 `leads` 表，用 `external_id='pool:<claim_id>'` 幂等去重。返回后官网把对应 `pool_claims` 标 `synced_at`、写 `pool_api_sync`。

> 选拉取为主：本地部署多在**内网**，官网（公网）主动推不进去；拉取不要求用户开放入站端口，也不需要公网证书。

**通道 3 · 下载版 API 推送（可选）**

会员在接入配置里登记自己 CRM 的公网 `base_url` 与他在 CRM 里生成的 API Key；官网领取时 `POST {base_url}/api/v1/leads`，**复用 CRM 现有对外线索 API**（`src/routes/leads-api.js` 的 `WRITE_FIELDS`、`external_id` 幂等、鉴权）。官网侧只负责出站，密钥用 AES-256-GCM 加密存 `push_secret_enc`。要求对方 CRM 已按 `docs/15` 配置授权 IP / 域名白名单，把这些官网出口 IP 加进白名单。

> 与用户既有约定一致：**授权 IP + 授权域名，仅后台超级管理员可操作**。官网侧的「API 接入审核」也只给超管，会员只能提交申请。

**幂等 & 审计**：三条通道统一用 `external_id = 'pool:<claim_id>'`；每次交付写 `pool_api_sync` / `pool_claims.status`；`disclosed_at` 记录完整联系方式首次披露时间。

## 7. 验证要点

1. **并发领取**：两请求同时领同一条，恰好一个成功
2. **组织隔离**：A 公司看不到 B 公司池线索；`self` 看得到本组织池、看不到他人私有线索
3. **trial 隔离**：试用账号只看自己试用组织的池，不能分配 / 强制回收
4. **双时钟**：保护期内不回收；72h 无首触回池；30 天无有效跟进回池；`note` 不续时钟
5. **无效不回池**：`status='invalid'` 永不出现在池中
6. **限额**：在库 50 / 每周 10 触顶被拒
7. **老库补列**：SQLite 与 PG 各跑一次 `migrate()`，`ensureColumns()` 幂等
8. **路由顺序**：`/api/leads/pool` 不被 `/api/leads/:id` 吃掉
9. **真实线索专项**：公开接口不返回公司全称 / 联系人 / 电话；独家线索第二人领取被拒；共享线索达 `max_claims` 后停领；授权凭证未填不能上架；授权到期自动下架；`claim_count` 并发不超卖
10. **领取门槛**：未开通试用 / 未审核 API 接入 / `frozen` 一律拒绝，文案明确
11. **API 通道**：凭证只能拿到**自己领过的**线索；`since` 增量不重复；`external_id='pool:<claim_id>'` 重放不产生重复线索；IP / 域名白名单外被拒；推送通道对方未配白名单时失败可重试
12. **合规留痕**：`agreed_at` + 协议版本 + IP 齐全；`disclosed_at` 记录完整联系方式披露时间
13. **SEO**：`seo-check` 全过，`/pool.html` 在 sitemap / llms，协议页 `noindex`
14. **回归**：CRM 25/25、官网 20/20、试用两端状态机对齐（14 天 / 30 天不变）

## 8. 埋点指标（补进 `docs/19` 第 6 节）

| 指标 | 算法 | 期望 |
|---|---|---|
| 池激活率 | 领取过真实线索的会员 / 开通数 | 真实线索应显著高于素材 |
| 二次回访 | 连续 ≥2 天有领取的会员数 | 衡量「养用户」 |
| 线索跟进率 | 领取后在 CRM 有 ≥1 条有效跟进 / 领取数 | **真实线索质量的核心指标** |
| 独家争抢率 | 独家线索在发布后 N 分钟内被领走的比例 | 高说明线索有吸引力 |
| 团队化信号 | 试用组织内成员数 ≥2 的占比 | 最靠近收费的先行指标 |
| 授权触发 | 第 11 人提示曝光 → 跳定价点击 | 直接衡量转化 |
| 质量淘汰率 | 因无效标记被下架的条数 / 总发布数 | 过高说明来源有问题 |

一期用 `pool_events` + `pool_claims` 直接统计，不必另建看板；看板仍属 P0 待办。
