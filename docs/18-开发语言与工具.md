# 18 · 开发语言与工具归类

> 一句话：**JavaScript 一门语言打通前后端，只有 1 个 npm 依赖，没有构建步骤。**
> 这份文档把两套系统（CRM 与销售官网）用到的语言、运行时、库、工具按用途归类，
> 并说明「为什么用它、不用别的」。

适用关系缩写：**CRM** = 集团 CRM（`crm-local`）｜**官网** = 销售平台（`AIOffice.aiemy.com`）｜**两者** = 都用到。

---

## 0. 一眼看清：前端用什么、后端用什么

最常被问的一题。两套系统结构一致，**前后端是同一门语言**，区别只在运行位置和承担职责。

| | 前端（浏览器） | 后端（服务器） |
|---|---|---|
| **语言** | JavaScript（ES Module） | JavaScript（ESM，`type: module`） |
| **运行环境** | 浏览器原生模块加载 | Node.js ≥ 22.5 |
| **结构语言** | HTML5 手写 | — |
| **样式语言** | CSS3（原生变量 + Flex/Grid） | — |
| **数据语言** | — | SQL（SQLite / PostgreSQL） |
| **框架** | **无**（不用 React / Vue） | **无**（不用 Express / Koa） |
| **运行时依赖** | **0** | 仅 `pg`（PG 模式才加载） |
| **构建步骤** | **无** | **无** |
| **代码入口** | `public/js/app.js`（CRM）<br>`public/assets/*.js`（官网） | `server.js` → `src/routes/index.js` |
| **怎么组织** | 每页一个 `views/xxx.js`，导出函数返回 HTML 字符串 | `src/routes/*.js` 里注册 `GET/POST/PATCH`，返回对象自动序列化 JSON |
| **怎么通信** | `js/api.js` 封装 `fetch`，Cookie 会话 | `src/http.js` 自研路由与统一错误信封 |

**具体到两套系统**

| 系统 | 前端 | 后端 | 数据库 |
|---|---|---|---|
| **CRM**（`crm-local`） | 原生 JS + HTML + CSS，`public/js/views/` 下 20+ 视图 | Node.js 零框架，`node:http` 自封装路由 | SQLite 默认 / PostgreSQL 18 可选 |
| **官网**（`AIOffice.aiemy.com`） | 原生 JS + HTML + CSS，多页静态站 | Node.js 零框架，同款自封装 | SQLite 默认 / PostgreSQL 可选 |

**三个容易搞错的点**

1. **没有 TypeScript**。全仓库 `.ts` 文件数为 0，`node --check` 就是全部语法检查手段，不需要编译。
2. **没有前后端分离的框架层**。前端不是 SPA，后端不返回 JSON 给前端渲染；CRM 的页面是「服务端发静态壳 + 前端 JS 拉数据填进去」，官网更彻底——HTML 是预渲染好的静态文件。
3. **「前端零依赖」是真的零**。没有 jQuery、没有图表库、没有图标字体、没有 UI 组件库；图表用内联 SVG 手绘，图标是 `js/icons.js` 里的 SVG path。

## 1. 语言

| 语言 | 用途 | 适用 | 版本要求 | 备注 |
|---|---|---|---|---|
| **JavaScript（ESM）** | 服务端全部逻辑 + 前端全部交互 | 两者 | Node ≥ 22.5 | 全项目 `type: module`，无 CommonJS 混用 |
| **HTML5** | 页面结构（登录页、工作台、落地页） | 两者 | — | 纯静态，无模板引擎、无 JSX |
| **CSS3** | 全部样式 | 两者 | — | 原生变量 + Flex/Grid；无 Sass/Less/Tailwind |
| **SQL** | 数据读写 | 两者 | SQLite 3 / PG 18 | 业务里一律写 `?` 占位符，方言差异集中收敛 |
| **Python** | 仅生成分享图与 favicon | 官网 | 3.x（实测 3.13） | 只为 Pillow 而生，不参与运行时 |
| **Bash** | 部署、发布、批量操作 | 两者 | Git Bash / Linux | `scripts/publish.sh`、部署命令行 |
| **Nginx 配置语法** | 站点托管与反向代理 | 两者 | nginx 稳定版 | 非编程语言，但属必须维护的配置资产 |

**为什么只用一门语言**：前后端同语言意味着字段名、错误文案、权限判断可以共用一套心智；
运维只需要装一个 Node，客户服务器少一样东西就少一种故障。

---

## 2. 运行时与依赖

| 项 | 内容 | 说明 |
|---|---|---|
| 运行时 | **Node.js ≥ 22.5** | 低于 22.5 用不了内置 `node:sqlite`，只能走 PostgreSQL |
| 包管理 | npm | 无 lock 之外的构建工具链 |
| 运行时依赖 | **只有 `pg` ^8.23** | 且仅 PostgreSQL 模式才会被加载；SQLite 模式下等于零依赖 |
| 前端依赖 | **0** | 没有 React/Vue/jQuery/图表库/UI 库 |
| 构建步骤 | **无** | 改完 `.js`/`.html` 刷新即生效，不需要 `npm run build` |

**零依赖怎么做到的**：HTTP 服务用 `node:http`、压缩用 `node:zlib`、
数据库用 `node:sqlite`、加密用 `node:crypto`、发信用 `node:net`+`node:tls`、
FTP 部署客户端自己用 `node:net` 实现（`scripts/ftp-deploy.mjs`）。

## 3. 数据存储

| 技术 | 角色 | 适用 | 说明 |
|---|---|---|---|
| **SQLite**（`node:sqlite`） | 默认库，单文件 `data/crm.db` / `data/site.db` | 两者 | WAL 模式；开箱即用，客户拷一个文件就完成迁移 |
| **PostgreSQL 18** | 可选库，生产用 | 两者 | CRM 建在 `crm` schema、官网在 `public` schema，同库互不干扰 |
| 双后端抽象 | 一套 API：`all/one/run/tx/idOf` | 两者 | 四个方言适配点：占位符、自增 id、事务连接、值类型 |

**为什么默认 SQLite**：中小企业客户的现实是「没有 DBA」。
单文件库可以直接拷走做备份，出问题能拿回本地排查；PostgreSQL 留给有运维能力的部署。

---

## 4. 前端技术

| 项 | 做法 | 说明 |
|---|---|---|
| 模块化 | 原生 ES Module（`import`/`export`） | 浏览器直接跑，不需要打包 |
| 视图层 | 每个页面一个 `views/*.js`，返回 HTML 字符串塞进容器 | 无虚拟 DOM、无 diff；状态变化就整体重渲染 |
| 请求层 | `js/api.js` 统一封装 `fetch` | 统一处理 401 跳登录、错误结构、`detail` 透传 |
| 组件 | `js/ui.js`（toast / modal / badge / 表单控件） | 手写，约 10KB |
| 图标 | `js/icons.js` 内联 SVG 路径 | 不引图标字体、不引图标库 |
| 图表 | CSS/HTML 手绘条形与进度 | 不引 ECharts/Chart.js |

**取舍**：这套做法在「表格 + 表单 + 弹窗」型后台上完全够用，
代价是没有组件生态；换来的是零构建、零依赖、任何一台机器 `node server.js` 就能跑。

## 5. 部署与运维工具

| 工具 | 用途 | 适用 |
|---|---|---|
| **Nginx** | 静态托管 + 反向代理（`/api/` → Node） | 两者 |
| **宝塔面板** | 建站、证书、运行目录、进程重启（站点根规则 `/www/wwwroot/<域名>`） | 两者 |
| **Pure-FTPd** | 文件上传通道（服务器只开 FTP，无 shell） | 两者 |
| **自研 `ftp-deploy.mjs`** | 零依赖 FTP 客户端：批量上传、按大小跳过、预渲染、MD5 回读 | 两者 |
| **pm2 / nohup** | 进程守护（当前用面板或 nohup 启动） | 两者 |
| **TrustAsia / Let's Encrypt 证书** | HTTPS | 两者 |
| **PostgreSQL 客户端** | 生产库运维 | 两者 |

**为什么自己写 FTP 客户端**：服务器只给 FTP，没有 SSH；而 npm 上的 FTP 库要么带一串依赖，
要么不支持被动模式 + 断点校验。自己写 200 行反而更可控。

## 6. 质量与自检工具（都在 `scripts/`）

| 脚本 | 作用 | 适用 |
|---|---|---|
| `node --check <file>` | 语法门禁，改完必跑 | 两者 |
| `scripts/verify.mjs` | CRM 端到端用例 | CRM |
| `scripts/seo-check.mjs` | 官网 54 项 SEO 自检（canonical、JSON-LD、缓存、穿越防护） | 官网 |
| `scripts/license.mjs` | 商业授权签发 / 校验 / 机器指纹 | CRM |
| `src/backup.js` | 两种数据库统一导出 JSON 快照 | CRM |
| `scripts/migrate-from-sqlite.mjs` | SQLite → PostgreSQL 数据搬迁 | CRM |
| `scripts/seo-assets.py` | 生成分享卡（1200×630）与 favicon | 官网 |

**临时测试脚本不入库**：涉及真实数据的联调一律复制一份库到临时目录跑，
跑完即删——避免测试数据污染生产，也避免把口令写进仓库。

## 8. 加密与安全：全部用 `node:crypto`，不引第三方

| 用途 | 算法 | 位置 |
|---|---|---|
| 密码存储 | **scrypt**（N=16384，16 字节盐） | `src/password.js` |
| 定长比较 | `timingSafeEqual` | 登录校验、内部接口密钥 |
| 会话令牌 | 32 字节随机 + 库里只存 **sha256** | `src/auth.js` |
| 试用密码可还原 | **AES-256-GCM**（`v1.iv.tag.body`） | 官网 `src/trial.js` |
| 商业授权 | **Ed25519** 签名（公钥内置、私钥在签发端） | CRM `src/license-core.js` |
| 机器指纹 | sha256(主机名+平台+架构) 取 12 位 | 同上 |

## 10. 明确不用什么（及原因）

| 没用 | 原因 |
|---|---|
| Express / Koa / Fastify | `node:http` + 自写 60 行路由表就够；引入框架为了省的那点代码，换来的是升级与安全补丁负担 |
| React / Vue / Svelte | 界面是「表格 + 表单 + 弹窗」，没有复杂状态；换来零构建、零依赖 |
| ORM（Sequelize / Prisma） | 业务 SQL 需要精确控制（组织树 `path` 前缀、三单匹配），ORM 反而绕 |
| Redis | 限流计数器进程内足够；单机部署没有跨实例需求 |
| Docker / K8s | 客户现场常常只有一台面板机；`node server.js` 是最低故障率的交付方式 |
| TypeScript | 类型收益真实，但需要编译步骤；本项目用 JSDoc 注释 + 自检脚本兜住主要风险 |
| Webpack / Vite | 没有要打包的东西 |
| Sass / Tailwind | CSS 变量 + 原生嵌套能力足够，多一层编译就多一处故障 |

## 11. 工具选型速查（遇到问题先看这张表）

| 我要… | 用什么 |
|---|---|
| 加一个接口 | `src/http.js` 的 `GET/POST/PATCH/DELETE` 注册，业务写在 `src/routes/*.js` |
| 加一张表 | `src/db.js` 的 DDL（只写 SQLite 版，PG 自动转换）+ 需要时在 `COLUMN_PATCHES` 补列 |
| 加一个页面 | `public/js/views/` 新建模块，在 `app.js` 路由表挂一行 |
| 发版 | `node scripts/ftp-deploy.mjs`，然后**重启进程** |
| 查 SEO 有没有破 | `node scripts/seo-check.mjs` |
| 给客户签授权 | `node scripts/license.mjs issue --to "客户名" --users 30 --expire 2027-11-01` |
| 备份数据 | `npm run backup`（两种库都支持） |
| 迁移到 PG | `node scripts/migrate-from-sqlite.mjs` |
