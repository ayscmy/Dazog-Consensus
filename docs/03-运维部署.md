## 1. 运行环境

| 项 | 要求 |
| --- | --- |
| Node.js | ≥ 18（本机 v22.22.2 已验证） |
| 依赖 | **无**，不需要 `npm install` |
| 端口 | 默认 4173 |
| 数据文件 | `data/db.json`（首次启动由 `data/seed.json` 生成） |
| 系统 | Windows（也用得在任何有 Node 的机器上） |

## 2. 启动与停止

```bash
cd D:\wwwroot\MSERM
npm start
```

等价于 `node server.js`。控制台出现两行日志即成功：

```
[22:10:31] 北辰 CRM 已启动 → http://localhost:4173
[22:10:31] 数据文件: D:\wwwroot\MSERM\data\db.json
```

- 停止：`Ctrl + C`
- 换端口：`set PORT=8080 && npm start`（PowerShell：`$env:PORT=8080; npm start`）
- 后台常驻（临时）：`start /b node server.js`

## 3. 开机自启（Windows）

### 方案 A：任务计划程序（不装任何东西，推荐）

1. 任务计划程序 → 创建任务
2. 常规：勾选"不管用户是否登录都要运行"、"使用最高权限运行"
3. 触发器：启动时
4. 操作：
   - 程序：`C:\Program Files\nodejs\node.exe`
   - 参数：`server.js`
   - 起始于：`D:\wwwroot\MSERM`
5. 设置：勾选"如果任务失败，重新启动"

### 方案 B：NSSM 注册为 Windows 服务

```bat
nssm install MSCRM "C:\Program Files\nodejs\node.exe" "D:\wwwroot\MSERM\server.js"
nssm set MSCRM AppDirectory D:\wwwroot\MSERM
nssm set MSCRM AppStdout D:\wwwroot\MSERM\data\service.log
nssm set MSCRM AppStderr D:\wwwroot\MSERM\data\service.log
nssm start MSCRM
```

好处是崩溃自动拉起、可用 `services.msc` 管理。

## 4. 内网访问

`server.js` 用的是 `server.listen(PORT)`，**默认监听所有网卡**，所以同一局域网内可直接访问：

```
http://<本机IP>:4173
```

查本机 IP：`ipconfig`，找 IPv4 地址（如 192.168.1.20）。

放行防火墙（管理员 PowerShell）：

```powershell
New-NetFirewallRule -DisplayName "MSCRM 4173" -Direction Inbound -Protocol TCP -LocalPort 4173 -Action Allow
```

> ⚠️ 此时**没有登录验证**，能访问该端口的人就能读写全部客户数据。仅在可信内网使用；要对公网开放，必须按第 5 节加反向代理 + 认证。

## 5. IIS 反向代理（放在 D:\wwwroot 下的原因）

项目在 `D:\wwwroot` 下，如果本机已有 IIS（宝塔/护卫神等面板同理），通常希望用 80/443 统一入口。

前置条件：IIS 安装 **URL Rewrite** 与 **Application Request Routing (ARR)**，并在 ARR 里启用 "Enable proxy"。

在站点根目录放 `web.config`：

```xml
<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <system.webServer>
    <rewrite>
      <rules>
        <rule name="MSCRM 反向代理" stopProcessing="true">
          <match url="(.*)" />
          <action type="Rewrite" url="http://127.0.0.1:4173/{R:1}" />
        </rule>
      </rules>
    </rewrite>
    <proxy preserveHostHeader="true" />
  </system.webServer>
</configuration>
```

注意：

- 反代后 Node 服务仍需在运行，IIS 只负责转发；
- 若要让 4173 不再对外暴露，可把 `server.js` 改为 `server.listen(PORT, '127.0.0.1')`；
- 公网访问务必配 HTTPS 与访问控制（IIS 的"IP 地址和域限制"或加一层 Basic 认证）。

## 6. 备份与恢复

```powershell
# 备份（带日期）
Copy-Item D:\wwwroot\MSERM\data\db.json "D:\backup\mscrm-$(Get-Date -f yyyyMMdd-HHmm).json"

# 恢复
Copy-Item D:\backup\mscrm-20261030-2230.json D:\wwwroot\MSERM\data\db.json -Force
```

恢复到运行中的服务**需要刷新浏览器**才会看到（页面只在启动时拉全量数据）。

建议加一条每日计划任务做备份：`schtasks /create /tn "MSCRM 备份" /tr "powershell -c Copy-Item ..." /sc daily /st 23:00`

## 7. 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面显示"无法连接本地服务" | Node 没启动，或端口不是 4173 | 重新 `npm start`，看控制台日志 |
| 打开是 502 / 空白页 | 前面有代理（IIS/面板）但后端未运行 | 启动 Node；或检查反代规则指向的端口 |
| `EADDRINUSE` | 4173 被占用 | `netstat -ano \| findstr 4173` 找 PID 后结束，或换 `PORT` |
| 侧栏显示"保存失败" | 服务已退出，或 `data/db.json` 无写权限 | 检查服务与目录权限 |
| 数据突然回到示例 | `db.json` 被删了，服务重启时用 seed 重建 | 从备份恢复 `db.json` |
| 中文输入法打不出字 | 若自行改过渲染逻辑导致输入框重绘 | 参考 [[01-设计思路]] 3.4 节，输入事件不要触发整页 `render()` |
| 端口能开但页面样式丢失 | `public/` 被移动或删除 | 确认 `public/index.html`、`styles.css`、`app.js` 都在 |

服务端没有日志文件，所有信息只打控制台。若用 NSSM 部署，标准输出会落到 `data/service.log`（见第 3 节）。

## 8. 目录权限

`data/` 需要**写权限**（服务要回写 JSON）。`public/` 与 `server.js` 只读即可。
若把项目放在受保护目录，注意给运行 Node 的账号（或其所在用户组）显式授权。
