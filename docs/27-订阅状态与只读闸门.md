# 订阅状态同步与只读闸门（P1-A）

> 边界：**CRM 不计费、不判定订阅周期**，只接收官网下发的结论并执行访问控制。
> 官网 `saas_subscriptions` 是状态权威；本文件的接口与闸门负责把结论落到 `tenants` 台账与统一入口。
> 与 `docs/26-多租户实例编排.md` 的关系：编排器负责拉起实例，本文件负责「实例里的组织还能不能写」。

## 1. 内部接口：`POST /api/internal/tenant/sync-status`

两道门与 `tenant/activate|renew|suspend|usage` 一致：`X-Internal-Key` 定长比较 + 回环 IP（`TRIAL_ALLOW_IPS` 可加白名单）。

请求体：

| 字段 | 必填 | 说明 |
|---|---|---|
| `code` / `email` | 二选一 | 定位租户（按 code 优先） |
| `status` | 是 | 官网订阅状态：`active` / `expiring` / `grace` / `frozen` / `expired` / `cancelled` |
| `expiresAt` | 否 | 同步到期日；缺省保留台账原值 |
| `graceUntil` / `reason` | 否 | 排障留痕 |

状态映射：

| 官网状态 | `tenants.status` | 登录态 |
|---|---|---|
| `active` / `expiring` | `active` | 恢复 `active`（若被冻结） |
| `grace` | `grace` | 保持可登录（只读在统一入口拦截） |
| `frozen` / `expired` / `cancelled` | `suspended` | `users.status='frozen'` |

幂等：状态与到期日都未变化时返回 `unchanged: true`，不重复写库、不重复改登录态。未知 `status` 返回 400，租户不存在返回 404。

## 2. 只读闸门

位置：`src/http.js` 的 `dispatch()`，在鉴权之后、业务 handler 之前统一拦截，避免逐个路由漏加。

规则（`src/tenant-guard.js`）：

- `grace`：所有写操作返回 **403 `TENANT_READONLY`**（可登录、可读，不可写）。
- `frozen` / `suspended` / `expired` / `cancelled`：写操作返回 **403 `TENANT_FROZEN`**。
- 豁免：`GET` / `HEAD` / `OPTIONS`、`/api/internal/*`、`/healthz`、`/api/auth/login|logout|sms/*`。
- 判定依据：`tenants.org_id = 当前用户 orgId` 的最新一条受限台账；无记录直接放行。

> 内部接口必须豁免：否则官网下发 `sync-status` 的请求本身会被闸门挡住，形成死锁。

## 3. 适用范围

- **主库 / 共享试用实例**：`tenants` 台账与业务库同库，闸门直接生效（试用转正租户已关联 `org_id`）。
- **独立部署实例**：闸门逻辑同样可用，前提是实例库里的 `tenants` 台账有该组织的状态记录。当前由编排器写主库台账，独立实例的状态回写由后续自动化补齐；未回写前独立实例的访问控制在 CRM 主库侧生效。
