# 11 · 组织分级、审批点名与离职交接（v2.3）

> 对应三个诉求：审批要指定到人、组织要做 1/2/3 级分类且上下级可见不跨域、离职先交接后停用并把客户转给别人。
> 代码：`src/auth.js`（分级规则）、`src/approval.js`（审批链与候选人）、`src/routes/admin.js`（用户/组织/交接）、`src/routes/accounts.js`（客户转让）。

## 一、审批：从"角色"到"人"

### 之前的问题

提交时只告诉用户"审批链：经理 → 总监"，但经理是谁、总监在哪，申请人看不到；组织里没配对应角色时，节点会被静默 `skipped`，单子看起来批完了，实际没人看过。

### 现在的做法

| 环节 | 行为 |
|---|---|
| 提交前 | `GET /api/approvals/preview?type=quote|contract&id=` 返回每一关的审批人（姓名/职称/组织）与候选人 |
| 弹窗确认 | 「提交审批 · 确认审批人」逐关列出；同一角色多人时可下拉改派 |
| 提交 | 前端把 `assignees`（角色→用户ID）随请求带上，服务端只接受该节点的合法候选人 |
| 缺人 | 直接 400，列出"缺少：销售总监"，提示先去组织里指定负责人——不再静默跳过 |

候选人按组织树**由近及远**排序：本部门 → 上级部门 → … → 集团；财务/法务没有组织归属时全局兜底。

审批通过后，时间线里显示的也是"王敏 · 销售一部经理 · 销售一部"，而不是一个角色标签。

## 二、组织：1/2/3 级分类

| 层级 | 典型形态 | 节点类型 | 谁管这一层 | 能授予的角色 |
|---|---|---|---|---|
| 1 级 | 北辰集团 | `group` | 系统管理员 / 总经理 | 管理员全部；总经理除管理员外 |
| 2 级 | 华东公司 | `company` | 销售总监 | 经理 / 客户经理 / 线索专员 |
| 3 级 | 销售一部 | `dept` | 销售经理 | 客户经理 / 线索专员 |
| 4 级 | 华北小组 | `team` | — | — |

层级不是手填的：`org_units.level` 由 `path` 深度自动回填（`/1/2/3/` → 3 级），新建组织时取父级 +1，最多 4 级。

### 看得见与看不见

- **人员可见**（通讯录、组织架构、交接候选人）：本组织子树 **+ 祖先组织链**。所以经理能看到自己的总监，总监能看到下属经理与业务员。
- **业务数据可见**（客户/商机/合同）：只向下看，`path LIKE '我的path%'`。上级的私单不会漏给下级，兄弟部门之间完全不可见（不跨域）。
- **写权限**：`canManageUser()` 三重校验——不能管自己、不能管管理员/总经理、不能跨出本组织子树，且授予角色不能超过自己的管理上限。

这样"上下级能看见"和"不能跨域"不是矛盾的：**人可见范围宽一格，数据可见范围守边界**。

## 三、离职：先交接，再停用

### 为什么必须"先交接"

业务员离职时名下往往有客户、进行中的商机、待审批单据。直接停用账号，这些资产会变成"孤儿数据"：客户没人跟、商机卡在阶段里、审批单永远等一个再也不会登录的人。

### 流程

```
选择人员 → 资产盘点（客户/商机/线索/合同/待审批）
        → 指定接收人（本部门优先，可选上级经理/总监）
        → 勾选要交接的资产
        → 一次事务：改归属 + 改组织 + 转审批节点
        → 账号置 left、写离职时间、删全部会话
        → 弹窗「已办理离职」并列出交接数量
        → 之后再登录：提示「已于 2026-10-31 11:19 离职，账号已停用」
```

### 规则细节

| 规则 | 原因 |
|---|---|
| 不能把状态直接改成 `left`，必须走交接 | 防止有人跳过交接直接停号，留下孤儿数据 |
| 至少保留一位在职管理员 | 避免把自己交接掉后没人能进系统 |
| 接收人必须在发起人的组织链内 | 不跨域；同时避免把客户塞给不相干部门 |
| 接收人没有某审批角色时，该节点不转派 | 转过去也批不了；接口返回 `approvalLeft`，由管理员到审批中心改派 |
| 离职时间精确到分钟并展示给登录者 | 满足"再登录要显示什么时候离职的" |
| 管理员可恢复账号 | 误操作或返聘；恢复后 `left_at` 清空，但审计日志仍在 |

### 客户转让（非离职）

客户列表勾选 → 「转让」→ 选接收人 →（可选）连带转移进行中商机。
合同、开票、回款记录保持不动——这些是财务凭证，不随负责人变更而迁移。

## 四、接口清单

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/approvals/preview?type=&id=` | 审批链预览：每关审批人 + 候选人 + 缺失项 |
| GET | `/api/admin/users` | 可见成员（含上级/下级关系、已离职状态、可否管理） |
| GET | `/api/admin/users/:id/handover` | 离职前资产盘点 + 接收人候选 |
| POST | `/api/admin/users/:id/handover` | 交接并办理离职（事务） |
| POST | `/api/admin/users/:id/restore` | 恢复离职账号（仅管理员） |
| GET | `/api/orgs` | 可见组织树（含 level、负责人、成员/客户数） |
| POST | `/api/admin/orgs` | 新建组织（自动算层级，最多 4 级） |
| GET | `/api/transfer-targets?module=account` | 转让/交接候选人（本部门 + 上级链） |
| POST | `/api/accounts/bulk-transfer` | 批量转让客户（可连带商机） |
| POST | `/api/accounts/:id/transfer` | 单个客户转让 |

## 五、演示路径

1. 用 `admin` 登录 → 系统 → 用户与组织：能看到「关系」列（同部门/上级/下级）和分级规则表；
2. 用 `dir01`（华东总监）登录：只能看到华东公司及以下，看不到华南的 ae04；
3. 用 `ae01` 新建一张 7% 折扣报价 → 提交 → 弹窗显示「部门经理：王敏 / 销售总监：李强」；
4. `admin` 对某个业务员点「办理离职」→ 看资产盘点 → 选接收人 → 确认 → 弹窗显示离职时间与交接数量；
5. 用该账号再登录 → 提示「已于某时间离职」。
