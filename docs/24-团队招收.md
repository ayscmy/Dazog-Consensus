# MSERM CRM · 团队招收（开源共建）

我们正在组建 **MSERM CRM** 开源项目的核心贡献者团队，欢迎认同"开源、务实、可落地"理念的开发者、测试、文档与产品同学加入。

## 项目愿景

打造一款**真正能用、看得懂、改得动**的集团级 CRM：流程完整、部署轻、接口开放，让中小团队也能拥有企业级的销售—回款管理能力。

## 我们在找这样的人

| 方向 | 你大概在做什么 | 我们期待你 |
|------|----------------|------------|
| 后端开发 | Node.js 服务、接口与数据库 | 熟悉 Node 原生 / ESM、SQL；理解权限与审批模型 |
| 前端开发 | 管理后台与数据可视化 | 能基于轻量方案实现表单、看板、报表 |
| 测试与质量 | 编写回归用例、压测 | 重视边界与异常，能补齐验收脚本 |
| 文档与社区 | 文档、示例、答疑 | 表达清晰，乐于把复杂讲简单 |
| 产品 / 实施 | 需求梳理、客户落地 | 懂销售 / 回款业务，能转化为功能 |

> 不论全职与否、不论资历深浅，只要有持续共建的意愿，我们都欢迎。

## 你能获得

- 真实业务场景下的全栈历练：**线索到回款全链路**，不是玩具项目。
- 与核心团队共同设计架构，贡献将被署名记录。
- 项目成熟过程中的社区影响力与共建荣誉。
- 优秀贡献者有机会进入**核心维护者**名单。

## 如何加入

1. 在 Gitee / GitHub 仓库 **Star / Fork**，先读 `README.md` 与 `docs/` 下的文档（建议从 `docs/23-项目介绍与简介.md` 入手）。
2. 从 `good first issue` 或文档勘误起步，提交你的第一个 PR。
3. 在 **Issue** 里做个自我介绍 + 你感兴趣的方向，我们会主动联系。
4. （可选）加入项目交流渠道，参与定期共建讨论。

> 所有正式联系方式以仓库 Issue 与官方公告为准；任何私下转账、索取敏感信息的请求都请勿理会。

## 共建约定

- 代码遵循仓库既有风格与提交规范，PR 请说明「做了什么 / 为什么」。
- 涉及客户数据的能力，必须经过**脱敏与权限评审**后方可合入。
- 重大变更先在 Issue 里讨论方案，再动手实现。
- 友好、耐心、对事不对人——这是我们协作的底线。

## 路线图（共建方向）

- 线索公海与官网客户池的深度联动；
- 对外线索 API 的限流、审计与多租户；
- 报表与经营看板；
- 国际化与多语言；
- 容器化与一键部署。

想从哪儿开始，就在 Issue 里告诉我们。期待与你一起把 MSERM CRM 做得更好。
