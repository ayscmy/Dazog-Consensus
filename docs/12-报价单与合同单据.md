# 12 · 报价单与合同单据

> 版本：v2.4（2026-10-31）
> 覆盖：报价单生成与发送（邮件 / 短信）、订单合同（发票式）、条款合同（模板 + 条款编辑）、合同编码规则、打印与配置。

---

## 一、报价单

### 1.1 生成

报价通过价格审批（含零折扣免审批）后，系统自动为该报价生成一张**客户可见的报价单**，并分配一个不可猜测的公开 token（`quotations.public_token`，24 位十六进制）。

- 访问地址：`/q/<token>`
- 免登录、无需账号，客户点开即看；页面自适应手机
- 只有 `approved` / `converted` 状态的报价可访问，其余状态返回「报价单不存在或已失效」
- 页面可由销售在线预览、复制链接、微信/邮件转发，或直接打印 / 另存 PDF
- 报价单**不包含成本、毛利率**等内部字段（服务端渲染时就不查成本）

报价单内容：公司抬头、报价单号 / 日期 / 有效期 / 版本、客户与供方信息、明细（产品、规格、单位、数量、单价、金额）、标准价合计 / 折扣率 / 优惠金额 / 报价合计（含税）/ 价税合计大写、报价说明、商务信息（付款方式、开户行、账号、关联商机）、双方确认签字栏。

### 1.2 发送给客户

报价抽屉 →「报价单」区块 →「发送给客户」，可勾选：

| 渠道 | 内容 | 失败/未配置时的行为 |
|---|---|---|
| 邮件 | 品牌化 HTML 邮件：客户称呼、单号、金额、折扣、有效期、明细摘要、附言、醒目的「查看完整报价单」按钮与纯文本链接 | 记录为 `simulated`，仍生成链接，可复制后自行发送 |
| 短信 | 按模板生成：`您好，{公司} 已为您生成报价单 {单号}，金额 {金额} 元，有效期至 {日期}。查看：{链接}` | 同上，记录 `simulated` |

每次发送都写入 `quote_sends`（渠道、目标、主题、正文、状态、服务商、错误、链接、操作人、时间），报价抽屉展示最近 5 条，`quotations.last_sent_at / send_count` 同步更新，并在报价时间线写一条活动记录。

状态含义：

- `sent`：SMTP / 短信网关返回成功
- `simulated`：未启用或未配置通道，链接已生成、记录已留痕
- `failed`：已配置但发送失败（保留错误信息便于排查）

### 1.3 发送通道配置

**系统设置 → 邮件发送（SMTP）**

| 配置项 | 说明 |
|---|---|
| 启用邮件发送 | 关闭时一律按「模拟发送」记录 |
| SMTP 服务器 / 端口 | 例如 `smtp.exmail.qq.com:465` |
| 使用 SSL/TLS | 465 端口开启（直连 TLS）；587 端口关闭后自动走 STARTTLS |
| 发件账号 / 授权码 | 支持 AUTH LOGIN；留空表示中继无需认证 |
| 发件地址 / 显示名 | 留空则用发件账号；显示名按 RFC 2047 编码 |

内置极简 SMTP 客户端（`src/mailer.js`，零依赖，基于 `node:net` / `node:tls`），支持 465 直连 TLS、587 STARTTLS、AUTH LOGIN、多行响应与点填充；20 秒超时。邮件为 `multipart/alternative`（纯文本 + HTML），主题与显示名均按 UTF-8 Base64 编码。

**系统设置 → 短信发送（HTTP 网关）**

向网关 `POST` JSON：`{ phone, content, sign, token }`，带 `Authorization: Bearer <token>`；返回 2xx 视为成功。变量：`{{company}} {{no}} {{amount}} {{valid_until}} {{link}} {{account}}`。

**系统设置 → 公司抬头**：报价单与合同的销售方 / 乙方信息（公司全称、税号、地址、电话、开户行、账号、法定代表人），一处维护、三处复用。

## 二、创建合同

### 2.1 入口

报价一旦通过（`status = approved` 且未生成过合同），会立刻出现在**合同页顶部的「待创建合同」**面板中，点「创建合同」直接进入类型选择；报价抽屉底部同样有「创建合同」按钮。零折扣报价提交后会自动跳到该流程。

### 2.2 选择类型

| 类型 | 适用 | 编号前缀 | 单据形态 |
|---|---|---|---|
| 订单合同 | 软硬件产品销售、实施服务打包报价 | `DD-年份-序号` | 发票式单据：买卖双方抬头 + 明细 + 税率税额 + 价税合计 |
| 条款合同 | 服务合同、采购合同、保密协议等需要条款文本的 | `HT-年份-序号` | 模板条款正文 + 甲乙方 + 签署页 |

合同编码由系统按年份自动递增（四位序号），同一年度内不重复；老数据 `HT2026xxxxxx` 与新格式互不影响。

### 2.3 订单合同（发票式）

- 购买方（甲方）：名称、纳税人识别号、地址、电话、开户行、账号、联系人；默认带出客户档案与主联系人，可补全
- 销售方（乙方）：取自系统设置的公司抬头
- 明细：来自已批准报价的快照（名称、规格、单位、数量、单价），生成后不再随报价变动
- 结算方式：**含税价**（单价含税，价税合计 = 明细金额）/ **不含税价**（单价不含税，另加税额）
- 税率：6% / 13% / 9% / 3% / 不征税
- 单据列：序号、货物或应税劳务名称、规格型号、单位、数量、单价、金额（不含税）、税率、税额；表尾合计
- 汇总：金额（不含税）、税额、已含折扣、价税合计（小写 + 大写，`src/money-cn.js` 转换）
- 固定条款段：交付与验收、付款方式（账期 + 收款账户）、质保与售后、争议解决、双方盖章栏

### 2.4 条款合同（模板）

1. 选择合同模板（内置：软件实施服务合同 / 产品采购合同 / 保密协议 NDA，可在 `contract_templates` 扩展）
2. 自动填充甲乙方、金额、账期、签订日期、项目名到条款占位符
3. 条款可在创建时逐条修改标题与正文、删除、追加；生成后草稿状态仍可在合同抽屉里「编辑条款」
4. 占位符：`{{buyer.name}}` `{{buyer.address}}` `{{buyer.contact}}` `{{buyer.phone}}` `{{buyer.tax_no}}` `{{seller.name}}` `{{seller.bank}}` `{{seller.account}}` `{{amount}}` `{{contract_no}}` `{{sign_date}}` `{{payment_terms}}` `{{project}}`

> 合同编号在生成时才知道，因此 `{{contract_no}}` 由服务端最后填充；前端编辑时显示占位提示，保存时后端统一替换。

### 2.5 查看与打印

- 合同抽屉 →「查看 / 打印单据」→ 新窗口打开 `/api/contracts/:id/document`（需登录，按数据范围鉴权）
- A4 排版，顶部工具栏「打印 / 另存为 PDF」在打印时自动隐藏
- 报价单同理：`/q/<token>` 页面自带打印按钮

## 三、接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/contracts/pending` | 已批准且未建合同的报价（合同页待办面板） |
| GET | `/api/contracts/templates` | 条款模板列表（含条款） |
| POST | `/api/contracts` | 创建合同，`kind=order\|terms`；带 `quotation_id` 时价格与明细锁定 |
| PATCH | `/api/contracts/:id` | 草稿可改标题/金额/税率/账期/日期/买方/明细/条款 |
| GET | `/api/contracts/:id/document` | 合同单据 HTML（订单合同 / 条款合同） |
| GET | `/api/quotations/:id/sheet` | 报价单数据：token、公开链接、HTML、联系人、通道就绪状态、发送记录 |
| GET | `/api/quotations/:id/sends` | 发送记录 |
| POST | `/api/quotations/:id/send` | 发送报价单，`channels=['email','sms']` + `email`/`phone`/`message` |
| GET | `/q/:token` | 客户免登录查看报价单（非 API，服务端直出 HTML） |

校验要点：

- 只有 `approved` / `converted` 的报价可发送、可查看公开链接
- 生成合同要求报价 `approved` 且未生成过合同；合同金额强制等于报价金额（不允许在合同环节改价）
- 单据接口与合同详情同样走 `canEditRecord` 数据范围校验
- 重复建合同、报价与商机不匹配、金额 ≤ 0、账期为负均返回 400 并给出可读提示

## 四、数据表

| 表 / 字段 | 说明 |
|---|---|
| `contract_templates` | 条款模板：`code`、`name`、`category`、`summary`、`clauses`(JSON 数组)、`builtin`、`status` |
| `quote_sends` | 报价发送记录：`quotation_id`、`channel`、`target`、`subject`、`content`、`status`、`provider`、`error`、`link`、`sent_by`、`created_at` |
| `contracts.kind` | `order` / `terms` |
| `contracts.tax_mode` | `included` / `excluded` |
| `contracts.buyer_json` / `seller_json` | 买卖双方快照 |
| `contracts.items_json` | 明细快照（名称、规格、单位、数量、单价） |
| `contracts.clauses_json` | 条款数组 `[{title, body}]` |
| `contracts.template_id` / `discount_rate` | 套用的模板、报价折扣率 |
| `quotations.public_token` | 报价单公开 token |
| `quotations.last_sent_at` / `send_count` | 最近发送时间、发送次数 |

## 五、权限与边界

- 创建合同需要 `contract` 模块权限，且必须对关联商机有编辑权（`canEditRecord`，受数据范围约束）
- 报价单只暴露对外字段，成本 / 毛利在服务端就被剔除，链接被转发也不会泄露
- 合同单据需登录，且只能看自己数据范围内的合同
- 合同一旦提交审批，条款与金额不能直接改（走变更流程）；仅 `draft` / `rejected` 可修改
- 邮件 / 短信未配置时不会「假装成功」：记录为 `simulated` 并明确提示，避免误以为客户已收到
