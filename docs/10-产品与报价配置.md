# 产品库、报价与审批阈值配置

> 本文对应 v2.1 的四项能力：**价格来自产品库**、**例外报价开关**、**按人配置的折扣审批点**、**阶段推进附件（≤1 MB，含图片）**。
> 相关文档：[[07-权限与流转矩阵]] · [[09-验证报告]] · [[README]]

## 一、为什么价格必须来自产品库

以前的报价是"标准价 + 成交价"两个数字手填。问题在于：

- 同一个产品，不同销售报的标准价不一样，客户一对比就露馅；
- 折扣率是手填两个数算出来的，填错了审批链也跟着错；
- 成本靠销售自己填，毛利口径无法统一。

改成明细行之后，**标准价和成本都从产品库取，前端传什么都不作数**（服务端会用产品记录覆盖），销售只能改「数量」和「成交单价」。折扣率由明细汇总反算，人算错不了。

## 二、产品库

菜单：`客户与销售 → 产品库`

| 字段 | 说明 |
|---|---|
| 产品编码 | 唯一，留空自动生成 |
| 产品名称 / 规格 / 单位 | 报价明细里显示的内容 |
| 产品线 | 用于分组（MES / WMS / 数据中台 / 服务…） |
| 标准价 | 报价基准，明细行的 list_price 取这里 |
| 成本 | 敏感字段，仅管理员/总经理/总监/经理/财务可见 |
| 底价 | 低于此价必须审批（当前用于提示，未强制拦截） |
| 状态 | 在售 / 停售。停售的产品不能用于新报价，历史单据不受影响 |

**权限**：所有能报价的角色都能看产品列表（只看到标准价）；只有 `admin` 和 `gm` 能新建/修改。删除时如果已被报价引用，只做停用，不物理删除。

新增产品时的价格会立刻对全集团生效，因为报价读的是同一张表。

## 三、报价明细的算法

```
行金额   = 数量 × 成交单价
标准价合计 = Σ(数量 × 标准价)
成交合计  = Σ(行金额)
折扣率   = (标准价合计 − 成交合计) / 标准价合计
成本      = Σ(数量 × 产品库成本)   ← 含例外项时由录入人填
毛利率   = (成交合计 − 成本) / 成交合计
```

规则：

- 成交单价 > 标准价 → 直接拒绝（不允许溢价，避免绕过折扣规则）；
- 数量 ≤ 0 → 拒绝；
- 报价至少要有 1 行明细；
- 提交审批前，若无成本且不含例外项 → 拒绝（缺成本算不出毛利）。

## 四、例外报价（产品库之外）

有些方案确实不在产品库里，比如"第三方系统接口改造 5 万"。这类项目走**例外项**：

1. 管理员在 `审批与报价设置 → 例外报价` 打开开关；
2. 勾选允许录入例外项的角色（默认：系统管理员、总经理、销售总监、销售经理）；
3. 该角色的人在报价编辑器里会看到「+ 例外项」按钮，可手工填名称、数量、标准价、成交单价、成本。

**为什么要有开关**：如果没有，销售就会把所有东西都做成例外项，产品库逐渐失效、价格体系回到手工时代。默认关闭、按角色授权，才能保证"绝大多数报价来自产品库"。

含例外项的报价会被标记（`has_custom = 1`），列表与详情都能看到「含例外项」徽章，审批摘要里也会写明。

### 例外项的录入与呈现

- 点「+ 例外项」弹出的是**独立一层弹窗**（叠在报价编辑器之上），不会顶掉编辑器；填完点「添加到明细」后弹窗自动收起，明细表立刻多一行。
- 注意：例外项**不写入产品库**，只属于当前这张报价单，因此它不会出现在「选择产品」下拉里，也无法被下次报价复用。这是刻意设计——避免产品库被一次性项目污染。
- 明细行显示「项目名称 + 规格说明 + 例外徽章」，**名称与规格会原样打印在报价单的两列里**（`产品 / 服务名称`、`规格说明`），并带入合同单据明细。
- 录错了不用删了重填：点击明细行里的名称即可再次打开弹窗修改（数量、单价也能直接在表里改）。
- 弹窗要求「标准价 > 0」且「成交单价 ≤ 标准价」；成本可不填，留空按 0 计毛利，仅经理及以上可见成本字段。

## 五、折扣审批阈值

### 前置规则：未让价不审价格（v2.2）

价格审批只为「让价」服务。报价折扣率 =（标准价合计 − 成交合计）/ 标准价合计：

| 场景 | 折扣率 | 流转 |
|---|---|---|
| 全部按产品库标准价成交 | 0 | **免价格审批**：提交即置为「已批准」，直接进入创建合同 |
| 任意一行低于标准价 | > 0 | 进入下方折扣审批链 |

- 判定容差 0.0001%，只用于吸收金额四舍五入的浮点误差；真实让价（哪怕 1 元）都会进入审批。
- 开关：`审批与报价设置 → 折扣审批阈值 → 未折扣报价免价格审批`（默认开启）。关闭后所有报价都要审批，用于过渡期或强管控场景。
- 免审批不生成 `approvals` 记录，但会在报价时间线写一条「未折扣报价，按规则免价格审批，提交即通过」，可追溯。
- 前端同步：报价编辑器底部实时提示「未折扣：免价格审批，提交后直接进入合同流程」，主按钮变为「创建并提交（免审批）」；报价抽屉里未折扣草稿显示「确认提交（免审批）」，提交成功后自动弹出「生成合同」。
- 价格一次落定：合同生成后只走合同审批（金额 / 账期阈值），价格不再二次审批。

> 接口层面，`POST /api/quotations/:id/submit` 在免审批时返回 `{ ok: true, skipped: true, status: 'approved', next: 'contract' }`，前端据此直接进入合同流程。

### 角色级阈值

`审批与报价设置 → 折扣审批阈值`：

| 设置项 | 默认 | 含义 |
|---|---|---|
| 部门经理可批折扣 | 5% | 折扣 ≤ 该值，只需经理审批 |
| 销售总监可批折扣 | 10% | 超过经理阈值但 ≤ 该值，经理 + 总监；超过则再加总经理 |

审批链算法（`src/approval.js`）：

```
chain = [经理]
if 折扣 > 经理阈值:  chain += 总监
    if 折扣 > 总监阈值:  chain += 总经理
```

### 单个人覆盖（不同管理员不同权限）

在同一个页面下方的「审批人折扣限额」表里，可以给**每个经理/总监**单独设置上限：

- 留空 → 继承角色阈值；
- 填了 → 以个人为准，比如给王敏设 3%，那么 5% 的折扣到他这儿就过不了，必须再走总监。

这解决了"同样是经理，新人权限应当更小"的问题，不用为每个人建一套角色。

> 实现上，`chainForDiscount(rate, orgId)` 会先用组织树找到当前这单的经理，读他的 `discount_limit`；没设才回落到全局设置。

## 六、阶段推进的附件

进入「需求确认」「方案报价」「商务谈判」「赢单」等阶段时，弹窗底部有「补充材料」上传区：

- 单个文件 ≤ 1 MB（可在设置里改），一次最多 5 个；
- 支持图片（png/jpg/webp/gif，上传后显示缩略图，点开可看原图）与常见文档（pdf/doc/docx/xls/xlsx/ppt/pptx/txt/md/csv）；
- 文件存在 `data/uploads/`，数据库只存元信息；
- 上传成功后会自动写一条跟进记录「上传附件：xxx」；
- 在商机详情抽屉的「材料与附件」区展示，图片是缩略图卡片，文档是文件卡片。

**权限**：附件跟着记录走——能看这条商机的人才能看它的附件，跨组织访问返回 403。删除只允许上传人、记录负责人或管理员。

**为什么限 1 MB**：这是给"关键截图、会议纪要、方案摘要"用的，不是网盘。大文件请放企业网盘，系统里放链接。真要放宽，改设置里的「单个附件上限」即可。

## 八、两个典型配置场景

**场景 A：新来的销售经理权限收紧**

1. 进「审批与报价设置」；
2. 在「审批人折扣限额」找到这位经理，填 `3`；
3. 保存。他从现在起只能批 3% 以内的折扣，超过自动升到总监。

**场景 B：某项目确实需要非标方案**

1. 打开「允许例外报价项」，勾选 `销售经理` 与 `客户经理`；
2. 销售在报价编辑器点「+ 例外项」，填名称与价格；
3. 提交后审批链照常按折扣计算，审批人能在明细里看到「例外」标记；
4. 项目结束、模式验证完，把开关关掉，回到全产品库报价。
