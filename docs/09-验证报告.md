## 修复二轮：详情抽屉内按钮全部失效（2026-10-31）

用户反馈三处操作无响应：**新建报价、写跟进、推进阶段**。排查后确认是同一根因，影响全部六个详情抽屉。

| 问题 | 原因 | 修复 |
|---|---|---|
| 抽屉内所有按钮点击无反应 | `const close = openDrawer(html, { onMount(root) {...} })` 中 `onMount` 是**同步执行**的，此时外层 `close` 还在暂时性死区（TDZ），回调里引用它抛 `ReferenceError`，导致后续所有 `onclick` 绑定被跳过 | 六处改为 `onMount(root, close)`，用 `openDrawer` 传入的形参遮蔽外层变量 |
| 「知道了」按钮无效（缺项提示框） | footer 用了 `data-close`，与弹窗头部的关闭按钮重名，`querySelector` 取到头部那个 | footer 改用 `data-c` |
| 修改密码弹窗「取消」无效 | 同上 | 同上 |
| 非负责人打开线索也能看到「记一笔」，点击后报错 | 按钮未按 `editable` 渲染 | 按 `editable` 隐藏，并在抽屉顶部提示「该线索由 X 负责，只能查看」 |
| 改动后浏览器仍跑旧脚本 | 静态资源 `max-age=300` | 改为 `no-cache` + ETag 协商缓存 |
| 报价列表页没有新建入口 | 只能从商机抽屉创建 | 列表页加「新建报价」，选商机自动带出金额 |

## 2.5 缺陷修复：例外项添加后丢失（2026-10-31）

**现象**：报价编辑器里点「+ 例外项」，在弹窗里添加后，报价单里看不到这条产品（明细为空或只剩产品库那几行）。

**根因**：`modal()` 使用全局唯一容器 `#modal`，每次打开都用 `innerHTML` 整体替换。从报价编辑器（本身是一个弹窗）里打开例外项弹窗时，**编辑器被直接销毁**；「添加到明细」写入的是一棵已经脱离文档的表格，于是数据只存在于内存里，提交时自然没有这行。

**修复**
- `public/js/ui.js`：`modal()` 改为**分层叠加**，每层是独立的 `.overlay` 节点，关闭时只移除自己；Esc 只关最上层；父弹窗关闭时连带回收叠在它上面的子弹窗，避免孤儿弹窗。
- `public/js/quote-editor.js`：例外项弹窗抽成可复用函数，新增「添加到明细」后保持编辑器存活并 toast 反馈；新增点击明细行名称再次修改（预填原值）；校验补全（成交单价留空按标准价、空值/负数拦截）。
