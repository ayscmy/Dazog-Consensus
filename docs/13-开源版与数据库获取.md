# 开源版与数据库获取

本文说明三件事：**仓库里有什么**、**没有数据库怎么跑**、**演示数据库怎么发**。

---

## 一、仓库边界

| 内容 | 是否入库 | 说明 |
|---|---|---|
| `src/` `public/` `server.js` | ✅ | 主系统全部代码 |
| `site/` | ✅ | 官网会员站（会员注册与安装包分发） |
| `docs/` | ✅ | 设计、数据模型、权限、部署、验证 |
| `data/crm.db` | ❌ | 运行时数据库 |
| `data/uploads/` | ❌ | 用户上传的附件（可能含真实资料） |
| `site/data/site.db` | ❌ | 官网会员库 |
| `release/` | ❌ | 演示库安装包（只存在于发布服务器） |
| `private/` | ❌ | 演示数据生成脚本（`seed.js`、打包脚本） |
| `memory/` `legacy/` | ❌ | 内部工作记录与 1.0 历史版本 |
| `.env` | ❌ | SMTP 口令、短信 Token |

`.gitignore` 已覆盖以上路径。提交前建议自查：

```bash
git status --short
git ls-files | grep -E '\.(db|sqlite|zip)$'   # 应该没有任何输出
```

## 二、为什么数据库不进仓库

1. **体积与噪音**：SQLite 文件每次运行都在变，`git diff` 无意义，仓库会迅速膨胀。
2. **不可撤销的泄露**：密码哈希、客户电话、合同金额一旦提交，即使后续删除也会留在历史里。
3. **升级冲突**：`git pull` 若带上数据库文件，会直接覆盖用户业务数据。
4. **商业边界**：代码开源、数据由官网会员获取，是这类项目的常见做法；数据本身也是产品的一部分。

代价是「clone 下来不能立刻看到满屏数据」。为此提供了两条路径：

- 空库 + 安装向导（2 分钟，适合自己录入）
- 官网会员下载演示库（1 分钟，适合先体验）

## 三、空库安装

```bash
git clone <repo> && cd mserm-crm
npm start
# 浏览器打开 http://localhost:8081 → 自动跳 /setup.html
```

安装向导做的事（`src/setup.js`）：

1. 在 `org_units` 创建根节点（type = `group`，path = `/<id>/`，level = 1）
2. 创建管理员账号（scrypt 散列），写入 `user_roles` 的 `admin`
3. 把「公司名称」写入 `settings.company.name` / `short_name`
4. 写一条 `audit_logs`，记录初始化
5. 之后 `GET /api/setup/status` 返回 `needed: false`，`/setup.html` 自动跳登录页

**安全约束**：`POST /api/setup` 只在 `users` 表为空时可用，第二次调用返回 403。管理员忘记密码时不能靠重装向导绕过，需要直接改库或走后台重置。

空库启动后需要自己补的最小数据集：

| 顺序 | 内容 | 位置 |
|---|---|---|
| 1 | 组织架构（公司、部门、团队） | 用户与组织 |
| 2 | 用户与角色 | 用户与组织 |
| 3 | 产品库（名称、规格、标准价、成本） | 产品库 |
| 4 | 客户与联系人 | 客户 |
| 5 | 公司抬头、折扣阈值、SMTP/短信 | 系统设置 |

## 四、官网会员站

官网是独立进程、独立数据库，与主系统**不共享任何表**，因此可以部署在不同机器。

### 启动

```bash
cd site
cp .env.example .env
# 至少改 SITE_ADMIN_EMAIL / SITE_ADMIN_PASSWORD
npm start                      # 或回到根目录 npm run site
```

默认 <http://localhost:8090>。

### 关键配置

| 变量 | 作用 |
|---|---|
| `SITE_ADMIN_EMAIL` / `SITE_ADMIN_PASSWORD` | 首个管理员；不填密码会随机生成并打印到控制台 |
| `SITE_RELEASE_DIR` | 安装包目录，默认 `../release` |
| `SITE_DAILY_DOWNLOAD_LIMIT` | 每会员每日下载次数，默认 20 |
| `SITE_MAX_UPLOAD_MB` | 后台上传单文件上限，默认 200 |
| `SMTP_*` | 注册验证码；不配置时验证码只打印到服务端日志，注册免验证 |
| `SITE_REQUIRE_CODE` | 配置 SMTP 后是否强制校验验证码，默认 1 |
| `SITE_SECURE_COOKIE` | HTTPS 部署时置 1 |

### 会员与下载

- 注册：`POST /api/auth/signup`，邮箱唯一，密码 ≥ 8 位且含字母数字
- 登录：`POST /api/auth/login`，失败 6 次锁定 10 分钟（IP + 邮箱）
- 下载：`GET /api/download/:id`
  - 必须登录，且会员状态为 `active`
  - 每日次数超限返回 429
  - 记录 `downloads`（会员、版本、IP、UA），并累加版本下载量
  - 支持 `Range`，浏览器可断点续传
- 防直链：下载地址带版本 id 而非文件名，未登录访问返回 401，无法像静态文件一样被外链

### 后台

`/admin.html`（管理员账号登录）：

- 上传安装包（`PUT /api/admin/upload`，请求体是二进制，避免引入 multipart 依赖）
- 登记版本：版本号、标题、更新说明、渠道（stable/beta）、发布状态
- 版本上下线、会员停用/启用、下载记录、操作日志

## 五、发布一个演示库（维护者）

`private/make-demo-db.mjs` 不在仓库中，只在维护者本地：

```bash
npm run demo       # 生成 release/mserm-demo-<version>.db 与 .zip、manifest.json
```

脚本流程：

1. 用临时路径 `CRM_DB` 建库并执行 `migrate()`
2. 调用 `private/seed.js` 写入演示数据（组织、用户、产品、客户、商机、报价、合同、回款）
3. `PRAGMA wal_checkpoint(TRUNCATE)` 后 `VACUUM INTO` 输出单文件（避免带上 `-wal`）
4. 计算 SHA256，生成 `INSTALL.md`（含演示账号表、体验顺序、校验值）
5. 打包 zip（deflate），写 `release/manifest.json`

然后在官网后台：

1. 「安装包」选择 `release/mserm-demo-<version>.zip`（或上传）
2. 填版本号与更新说明（会员中心与首页会展示）
3. 发布

> 每次重新生成，SQLite 页面布局与随机 Token 都会让 SHA256 变化，属于正常现象。发布后以 `manifest.json` 为准。

## 六、数据库升级

代码升级与数据升级是分开的：

- `migrate()` 在每次启动时执行，只做 `create table if not exists` 与 `add column if not exists`
- **不删表、不改列类型、不重命名**
- 业务上需要废弃的字段保留在表里，代码不再读写

因此：

- 空库 → 直接建到最新结构
- 老库 → 启动时补齐缺失的列，历史数据保留
- 演示库 → 与当前版本代码的结构一致；跨大版本升级时，官网会同时提供新的演示库

升级建议流程：

```bash
npm run backup           # 先备份到 data/backups/
git pull
npm start                # 观察日志中的迁移提示
```

## 七、常见问题

**Q：`npm start` 后没有演示账号？**
A：这是预期行为。开源仓库不含演示数据，请走安装向导，或下载演示库覆盖 `data/crm.db`。

**Q：可以只用官网、不要主系统吗？**
A：可以。`site/` 是独立服务，但它的价值是分发主系统的演示库。

**Q：能把演示库放进自己的仓库吗？**
A：不建议，也不符合许可证外的最佳实践——里面有账号哈希与虚构客户数据，容易被误认为真实数据。请让使用者自行注册下载。

**Q：官网端口 8090 被占用？**
A：改 `site/.env` 的 `PORT`，例如 8091，同时修改主系统的 `SITE_URL`。

**Q：会员下载后放到 `data/crm.db` 启动报「数据库版本不兼容」？**
A：说明演示库比代码新。拉最新代码，或下载与代码同版本的安装包。

## 八、发布到 Gitee

### 1. 先把占位地址换成自己的

仓库里的 `gitee.com/mserm/mserm-crm` 是占位地址，出现在 README、package.json、官网默认仓库链接等处。一条命令替换：

```bash
./scripts/set-repo.sh <你的空间地址> [仓库名]
# 例：./scripts/set-repo.sh jacky mserm-crm
```

### 2. 建仓并推送

**方式 A：网页建仓（最简单）**

在 Gitee 新建仓库（不要勾选「初始化仓库」），然后：

```bash
git remote add origin https://gitee.com/<你的空间>/mserm-crm.git
git push -u origin main
```

**方式 B：脚本自动建仓**

到「设置 → 私人令牌」生成令牌（勾选 `projects`），然后：

```bash
GITEE_TOKEN=你的令牌 GITEE_OWNER=你的空间 ./scripts/publish-gitee.sh
```

脚本会先检查有没有把 `.db` / `release/` / `private/` 提交进版本库，再创建仓库并推送；令牌只用于本次推送，不写入 `.git/config`。

### 3. 建仓后的设置

| 项目 | 建议 |
|---|---|
| 开源许可证 | 选 AGPL-3.0（Gitee 会自动识别 `LICENSE`） |
| 项目简介 | 一句话说明 + 「代码开源，演示数据库官网会员免费下载」 |
| 标签 | `crm` `sqlite` `nodejs` `报价` `合同` `审批` |
| Issue 模板 | `.gitee/ISSUE_TEMPLATE.zh-CN.md` 已就位，Gitee 会自动读取 |
| PR 模板 | `.gitee/PULL_REQUEST_TEMPLATE.zh-CN.md` 同上 |
| 分支保护 | 保护 `main`，要求 PR 合并 |

### 4. 后续发版

```bash
# 维护者本地
npm run demo                     # 生成新的演示库安装包（private/ 脚本）
# 官网后台发布该安装包，会员即可下载

git add -A && git commit -m "chore: release v2.6.1"
git tag v2.6.1 && git push origin main --tags
```

Gitee 的「发行版」可以直接挂 `release/*.zip`，但**不要**把它提交到仓库——发行版附件与 Git 仓库是两套存储。
