# 04 · 接口说明

> ⚠️ 本文档描述 **1.0 单机原型**（JSON 文件存储、无登录）。当前版本为 2.0 网络版，请优先阅读 [[06-网络版架构]] · [[07-权限与流转矩阵]] · [[08-部署与运维]]。


> 服务端只有 4 个接口，全部在 `server.js` 里。返回 [[README]]

---

## 总览

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/db` | 拉取全量数据 |
| PUT / POST | `/api/db` | 整库覆盖写入 |
| POST | `/api/reset` | 恢复示例数据（用 `seed.json` 覆盖 `db.json`） |
| GET | `/api/health` | 存活检查 |
| GET | `/*` | 静态文件；未知路径（无扩展名）回落 `index.html` |

除 API 外不做任何路由，没有鉴权、没有 CORS（同源）。

---

## 1. GET /api/db

返回 `data/db.json` 的原始内容，`Content-Type: application/json; charset=utf-8`，`Cache-Control: no-store`。

前端在 `boot()` 里调用一次，把结果放进 `state.db`。

```bash
curl http://localhost:4173/api/db
```

## 2. PUT /api/db

整库覆盖。请求体就是完整的数据库对象。

- 校验：必须是合法 JSON，且 `companies` 为数组；否则 400。
- 写入方式：先写 `db.json.tmp`，再 `rename` 覆盖 → 原子操作，不会产生半个文件。
- 服务端会自动写入 `meta.updatedAt`，调用方不用管。

请求：

```bash
curl -X PUT http://localhost:4173/api/db \
  -H "Content-Type: application/json" \
  --data-binary @body.json
```

响应：

```json
{ "ok": true, "savedAt": "2026-10-30T14:32:10.123Z" }
```

**前端写入策略**：任何修改（字段编辑、新建、删除、拖拽换阶段）都调用 `save()`，默认 400ms 防抖后整库 PUT；拖拽与删除走 `save(true)` 立即提交。失败时侧栏状态点变红并提示。

### 为什么不做资源级接口

`POST /companies`、`PATCH /deals/d1` 这一套需要维护 ID 生成、字段校验、级联规则，且并发写仍要处理。单机单用户下，整库 PUT 的服务端代码只有 10 行，前端也不需要处理局部失败回滚。代价是并发写会互相覆盖——这在多人场景下必须改造，见 [[01-设计思路]] 第 7 节。

## 3. POST /api/reset

用 `data/seed.json` 覆盖 `data/db.json`。侧栏底部"恢复示例数据"调用的就是它（前端会先 `confirm`）。

```bash
curl -X POST http://localhost:4173/api/reset
# {"ok":true}
```

**会丢失当前所有改动**，无二次确认（确认在前端做）。

## 4. GET /api/health

```json
{ "ok": true, "uptime": 128.42 }
```

`uptime` 是进程运行秒数，可用于探活脚本。

## 5. 静态资源

- `/` → `public/index.html`
- `/styles.css`、`/app.js` → 对应文件
- 路径解析做了目录穿越防护：解析后的绝对路径必须位于 `public/` 内，否则 403。
- 无扩展名且文件不存在时回落 `index.html`（单页应用习惯，虽然本应用只有一个页面）。
- 所有静态响应 `Cache-Control: no-store`：开发期改完刷新即生效，不需要清缓存。

## 6. 深链接（前端路由，非服务端接口）

| 地址 | 行为 |
| --- | --- |
| `/#/companies` | 打开公司列表 |
| `/#/deals` | 打开商机（默认看板） |
| `/#/deals/d1` | 打开商机列表 + d1 的详情抽屉 |
| `/#/people/p3` | 打开联系人 p3 |

由 `app.js` 的 `parseHash()` / `syncHash()` 处理，使用 `history.replaceState` 同步地址栏，不产生历史堆栈膨胀。手改地址栏会触发 `hashchange` 正常跳转。

## 7. 请求体限制

`MAX_BODY = 8MB`（`server.js` 顶部常量）。超过直接断开连接并返回错误。按当前数据规模（几十 KB）远未触及，若将来要传附件需一并调整。
