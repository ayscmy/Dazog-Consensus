- 设计依据：官网 `docs/12-客户数据库与双向同步.md`（用户 2026-11-08 需求：官网客户数据库与 MSCRM 双向 API 对接）。
- 复用：`src/routes/leads-api.js` 的 v1 范式（`apiGet/apiPost` + `auth:'api'` + `requireScope` + `scopeSql/inScope` + `external_id` 幂等）；`src/api-auth.js` 的 Bearer 鉴权与 IP 白名单；`api_clients` 表（已含 `owner_id`/`org_id`/`pool_on_missing`/`scopeList`）。

---

## 1. 背景

官网建了独立的「客户数据库」（`customer_directory`），需与 crm-local 的客户/档案互通：
- **官网 → CRM**：官网把抓到的客户公司作为「客户档案（account）」推入 CRM 对应组织。
- **CRM → 官网**：CRM 里已有的客户账号回流到官网名录（不回环）。

CRM 侧只需新增 **对外 v1 accounts 接口**（创建 + 增量拉取），复用现有 leads 接口的鉴权、作用域、幂等范式。

## 2. 新增端点（`src/routes/accounts-api.js`，注册进 v1 路由）

| 方法 | 路径 | 作用域 | 说明 |
|---|---|---|---|
| POST | `/api/v1/accounts` | `account:write` | 创建客户账号，幂等（external_id） |
| GET | `/api/v1/accounts?since=&limit=` | `account:read` | 增量拉取，供官网回填名录 |
| GET | `/api/v1/accounts/:id` | `account:read` | 单条（可选，联调用） |
| PATCH | `/api/v1/accounts/:id` | `account:write` | 更新（可选，联调用） |

## 4. 创建端点实现要点（镜像 `POST /api/v1/leads`）

```js
apiPost('/api/v1/accounts', async ctx => {
  requireScope(ctx.client, 'account:write');
  const b = ctx.body || {};
  const externalId = str(b.external_id, 64);          // 官网带来 'dir:<id>'
  if (externalId) {
    const exist = await one('select * from accounts where external_id = ?', externalId);
    if (exist && (await inScope(ctx.client, exist))) {
      return ok(ctx, { ...accountView(exist), duplicated: true }, 200);  // 幂等命中
    }
  }
  const orgId = ctx.client.org_id || (await apiInOrg(ctx.client));
  const now = nowIso();
  const r = await run(`insert into accounts(name,short_name,industry,scale,region,level,
       website,address,phone,source,external_id,org_id,created_by,created_at,updated_at)
     values(?,?,?,?,?,?,?,?,?,?,?,?,?,?,?)`,
    data.name, data.short_name??null, data.industry??null, data.scale??null, data.region??null,
    data.level??null, data.website??null, data.address??null, data.phone??null,
    data.source ?? '官网客户库', externalId, orgId, ctx.client.owner_id||null, now, now);
  const id = idOf(r);
  if (data.contact_name) {
    await run(`insert into contacts(account_id,name,title,phone,email,is_primary,created_by,created_at,updated_at)
      values(?,?,?,?,?,1,?,?,?)`, id, data.contact_name, data.contact_title??null,
      data.contact_phone??null, data.contact_email??null, ctx.client.owner_id||null, now, now);
  }
  await auditApi(ctx, 'POST /api/v1/accounts', 'account', id, { name: data.name, external_id: externalId });
  const saved = await one(`${SELECT_ACCOUNT} where a.id = ?`, id);
  return ok(ctx, { ...accountView(saved), duplicated: false }, 201);
});
```

- `accountView()` 返回字段与 `leadView()` 同级（id/external_id/name/.../org_id/org_name/created_at/updated_at）。
- `SELECT_ACCOUNT` 仿 `SELECT_LEAD` 左连 `org_units` 取 `org_name`。
- 作用域校验：复用 `inScope(client, account)`（按 `org_units.path` 前缀）。
- 防环：官网推来的 `external_id='dir:<id>'` 命中即 `duplicated`，绝不重复建；官网拉取回流时据此判断只更新不新建（见官网 docs/12 §3/§8.2）。

## 5. 增量拉取端点（供官网回填）

```js
apiGet('/api/v1/accounts', async ctx => {
  requireScope(ctx.client, 'account:read');
  // 注意：dispatch 把 query 解析成普通对象 ctx.query（Object.fromEntries），不是 URLSearchParams
  const q = ctx.query;
  // since 缺失时必须取空字符串，否则 str() 返回 null 会让 `? = ''` 退化为 NULL 过滤，整条 WHERE 为假
  const since = q.since ? String(q.since).slice(0, 60) : '';
  const limit = Math.min(Number(q.limit) || 200, 500);
  const sc = scopeSql(ctx.client, 'a');
  const rows = await all(`select a.*, o.name as org_name
      from accounts a left join org_units o on o.id=a.org_id
     where ${sc.sql} and (a.updated_at > ? or ? = '')
     order by a.updated_at asc limit ?`,
    ...sc.params, since, since, limit);
  const items = rows.map(accountView);
  const nextSince = items.length ? items[items.length-1].updated_at : (since || nowIso());
  return ok(ctx, { items, nextSince, count: items.length });
});
```

- 不带 `since`：返回最近更新的（或按 `updated_at > ''` 全量首拉，前端用 `nextSince` 续拉）。
- 与官网 `pullFromCrm()` 的 `last_since` 对齐。
